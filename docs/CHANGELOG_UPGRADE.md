# Upgrade Changelog, Evidence Map & Post-Upgrade Audit (`MD-Confirm RTOS`)

This document consolidates the software credibility upgrades applied to `CenterDigitalTrust/MD-Confirm-RTOS` from pre-upgrade baseline [`08c73fe`](../README.md) through commit `370cb0e`, tracks every component that remains **`UNTESTED ON QNX`**, maps every [`README.md`](../README.md) claim to its concrete evidence artifact or status label, details remaining hardware dependencies, and re-runs the Task 1 code audit checklist ([`docs/UPGRADE_AUDIT.md`](UPGRADE_AUDIT.md)) against the upgraded codebase.

**Status Labels Used Throughout:**
- **`MEASURED`**: Measured on physical camera hardware, real image corpora, or bare-metal target silicon.
- **`SIMULATED`**: Synthetic inputs / simulated QNX daemon logic / QEMU x86_64 measurements / host unit tests.
- **`UNTESTED ON QNX`**: Modified QNX target `.cpp`, build rules, or shell scripts not compiled with QNX SDP 8.0 (`qcc`/`q++`) or executed in QNX QEMU.
- **`NOT YET MEASURED`**: Evaluation harness exists, but real-dataset or bare-metal measurements have not yet been executed.
- **`ROADMAP`**: Design target not yet implemented or enforced.
- **`BOUNDARY`**: Structural perimeter limitation outside software verification alone.

## 2. Changes Marked `UNTESTED ON QNX`

Due to proprietary BlackBerry QNX SDP 8.0 headers (`<sys/neutrino.h>`, `<sys/dispatch.h>`, `<sys/resmgr.h>`, `<sys/syspage.h>`, `qcc`/`q++`), QNX target binaries are **not built in GitHub Actions or on the Windows/Linux host**. Every QNX target binary, QNX build/header wrapper, and target script modified across Tasks 2–7 remains **`UNTESTED ON QNX`**:

| Artifact | Task(s) Modified | What Is Host-Tested vs `UNTESTED ON QNX` |
|---|---|---|
| [`qnx/Makefile`](../qnx/Makefile) | 2, 3, 5, 7 | **`UNTESTED ON QNX`**: QNX SDP 8.0 `q++`/`qcc` cross-compilation not executed. |
| [`qnx/common/mdfp_protocol.h`](../qnx/common/mdfp_protocol.h) | 2, 3, 5, 7 | **`UNTESTED ON QNX`**: IPC struct layout (`MdfpVerifyMsg`, `MdfpVerifyReply`, `MdfpSealMsg`) not compiled with `<sys/neutrino.h>` (`MdfpStatsPayload` in `mdfp_seqlock.h` is host-tested). |
| [`qnx/capture/md-capture.cpp`](../qnx/capture/md-capture.cpp) | 2, 5, 7 | **`UNTESTED ON QNX`**: Core helpers (`mdfp_seqlock.h`, `mdfp_ingest.h`) host-tested; QNX pulse loop, `MsgSend()`, SHM attach/re-attach, and stats field copying untested on QNX. |
| [`qnx/verify/md-verify.cpp`](../qnx/verify/md-verify.cpp) | 5, 7 | **`UNTESTED ON QNX`**: Core logic (`mdfp_ingest.h`, `mdfp_signals.h`) host-tested; QNX `MsgReceive`/`MsgReply`/`MsgSend` wrapper and CLI parser untested on QNX. |
| [`qnx/seal/md-seal.cpp`](../qnx/seal/md-seal.cpp) | 2, 3, 5 | **`UNTESTED ON QNX`**: Core logic (`mdfp_seal_core.h`, `mdfp_signer.h`, `mdfp_merkle.h`, `mdfp_canon.h`, `tweetnacl.c`) host-tested; QNX `MsgReceive`/`MsgReply`, `/data` mkdir, and default key provisioning untested on QNX. |

## 4. What Still Needs Hardware

Software upgrades in host tooling, cryptographic structure, and C++ unit coverage cannot close gaps that fundamentally depend on physical silicon or bare-metal targets:

1. **Real-Sensor ROC Across Temperature (`NOT YET MEASURED`):**
   - Run [`host/prnu-eval/`](../host/prnu-eval/) on licensed Dresden Image Database and VISION corpora to establish empirical consumer baseline metrics ([`docs/PRNU_RESULTS.md`](PRNU_RESULTS.md)).
   - Collect uncompressed raw Bayer frames from target automotive CMOS sensors (e.g., Sony IMX390 / ON Semi AR0820) across automotive operating temperatures (`-40°C` to `+85°C`) to characterize dark current, thermal gain drift, LED-flicker-mitigation (LFM), HDR split-pixel impact on PRNU SNR, real $N_{\text{attack}}$ thresholds, and whether physical sensors support deterministic per-frame exposure/gain modulation for challenge-response.
2. **Real Timing & Jitter on Bare Metal (`NOT YET MEASURED`):**
   - All existing QNX latency and jitter files ([`docs/evidence/jitter_baseline.json`](evidence/jitter_baseline.json), [`docs/evidence/jitter_under_100_curls.json`](evidence/jitter_under_100_curls.json)) reflect QEMU x86_64 host VM scheduling (`mean_us ≈ 5230–5515 µs`, `max_us ≈ 501,181 µs`).
   - Measuring microsecond interrupt response, interrupt-to-thread wakeup, pipeline WCET, and priority preemption requires bare-metal automotive target hardware (and moving `md-capture` / `md-verify` / `md-seal` off synchronous single-threaded blocking `MsgSend` and $O(N)$ full-tree rebuilds).
3. **HSM / TPM Hardware Key Protection (`ROADMAP`):**
   - Today [`qnx/common/mdfp_signer.h`](../qnx/common/mdfp_signer.h) uses `FileSigner` with software Ed25519 keys stored on the filesystem (`0600` check), and [`qnx/seal/md-seal.cpp`](../qnx/seal/md-seal.cpp) still carries `g_demo_seed` for automated bench provisioning when no explicit key exists. Root or filesystem read access trivially extracts the key; `swtpm` emulates TPM calls in software only.
   - Production requires implementing [`HardwareTokenSignerStub`](../qnx/common/mdfp_signer.h) against a physical PKCS#11 HSM, hardware TPM 2.0, or SoC Secure Element with non-exportable signing keys (and hardware-backed sensor secret provisioning if challenge-response is deployed).
4. **MIPI CSI-2 / Hardware DMA Ingestion Boundary (`ROADMAP`):**
   - Currently `/mdfp_frame_shm` is a single-slot `0666` POSIX shared memory segment populated by synthetic [`qnx/sensor-sim/md-sensor-sim.cpp`](../qnx/sensor-sim/md-sensor-sim.cpp). While `md-capture` now stops *post-copy* TOCTOU via `PrivateFrameSnapshot`, any process able to open `/mdfp_frame_shm` *before* `md-capture` copies can still forge frames ([`docs/TRUST_BOUNDARY.md`](TRUST_BOUNDARY.md)).
   - Production requires real MIPI CSI-2 receiver + ISP DMA ring buffers mapped read-only to `md-capture` with IOMMU/SMMU hardware isolation and authenticated kernel driver credentials.
